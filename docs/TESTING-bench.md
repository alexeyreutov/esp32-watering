# Чек-лист проверки на стенде

Порядок важен: каждый шаг проверяет то, на что опираются следующие. Результаты (числа!) записывайте в README §10.

## 0. Без воды, без насоса

1. Залить прошивку (`firmware/README.md`), открыть монитор порта 115200.
2. Экран: в верхней строке % и значок батареи, по центру `--:--`. Картинка сдвинута / мусор → флаг `WAT_OLED_SH1106` (README прошивки).
3. Первый старт без Wi-Fi: в логе `[main] ready, mode session`, через 15 с `[net] AP Watering-XXXX`, на экране значок Wi-Fi и «AP». Подключиться телефоном (пароль `watering`), открыть `http://192.168.4.1`.
4. Вкладка «Система»: задать Wi-Fi, **пароль администратора**, часовой пояс. После переподключения открыть `http://watering.local` или IP из монитора порта.
5. Время в шапке совпадает с реальным (NTP). Если нет интернета — время берётся с браузера при открытии страницы.

## 1. АКБ и датчик уровня

1. Мультиметр на B+ → сравнить с «АКБ» в шапке. Поправка делителя = мультиметр / показание × текущая поправка.
2. Датчик уровня в воздухе / в воде → индикатор «Вода есть / Нет воды» меняется. Если наоборот — переключить «"Вода есть", когда на входе» в «Системе».
3. Отключить АКБ (питание с USB) → «АКБ не найден», ручной полив блокируется с причиной «АКБ не определяется» (если проверка АКБ включена).
4. **Тревоги:** датчик уровня в воздух → нажать кнопку дважды (сон → пробуждение) → загорелся красный LED, на экране перечёркнутая капля, в журнале «Тревога: нет воды». Уложить спать кнопкой → LED **продолжает гореть** во сне. Вернуть датчик в воду → снова дважды кнопку → LED погас, «Тревога снята».
5. То же с АКБ: лабораторный БП вместо 18650, 3.4 В → пустая мигающая батарея и красный LED; 3.9 В + пробуждение → снято.

## 2. Один модуль на коротком проводе

1. ADDR → GND (0x48). Модуль 1 в «Обзоре» — «на связи».
2. Мультиметр на ALRT относительно GND: после включения — ~3.3 В (клапан закрыт).
3. «Тест клапана»: ALRT → ~0 В, клапан щёлкает, через 5 с закрывается. В журнале «Тест клапана завершён».
4. **Отказоустойчивость:** во время теста клапана нажать RESET на ESP32 → после загрузки в журнале «После сброса клапан был открыт — закрыт», клапан закрыт.
5. Во время теста клапана выдернуть SDA → клапан остаётся открытым до восстановления связи (ADS1115 держит состояние). База показывает аварию и повторяет закрытие каждые 5 с; после возврата провода — «Клапан закрыт, авария снята». *Это ожидаемое поведение — см. README §6 «Известные ограничения».*

## 3. Калибровка датчика влажности

1. Датчик в воздухе → «Сухо». В стакане воды до линии → «Мокро». Разница raw должна быть > 500 (обычно 8000–11000 на 3.3 В).
2. Воткнуть в сухую / политую землю → проценты правдоподобны и стабильны (±2% между измерениями).
3. Проверить с работающим клапаном соседнего модуля: показания не должны прыгать (прошивка в это время не измеряет, но проверка нужна для ручных измерений после полива).

## 4. Насос и вода

1. Насос в баке, клапан на тестовой капельнице. Ручной полив 10 с: последовательность «клапан → насос → насос стоп → клапан закрыт» видна по звуку и в журнале.
2. Замерить расход: мл за 60 с на каждом модуле. Записать — по нему выбирается длительность.
3. Во время полива вынуть датчик уровня из воды → через ~2 с «Полив прерван: кончилась вода».
4. «Остановить всё» во время полива → насос стоп, клапан закрыт, «остановлено вручную».
5. **Просадка АКБ:** на полуразряженном аккумуляторе (≈3.5 В) запустить полив и посмотреть, не перезагружается ли ESP32 при старте насоса. Если в журнале «Перезагрузка во время работы насоса» — питание насоса нужно развязать (конденсатор 1000 мкФ у насоса, отдельная ветка, толще провод).

## 5. Линия целиком

1. Все модули на штатном кабеле, адреса 0x48…0x4B.
2. 100 подряд «Измерить все» (можно скриптом: `POST /api/action {"cmd":"measure","module":-1}`) — ни одного «Ошибка чтения датчика».
3. На дальнем модуле включить `lineSense`, полив 30 с → в журнале «Напряжение на модуле при открытом клапане». Ниже ~4.5 В для 5-вольтового клапана — толще провод питания.
4. Осциллограф на SDA/SCL у дальнего модуля: фронты успевают подняться (< ~5 мкс при 20 кГц).

## 6. Расписание и сон

1. Поставить время проверки модуля через 2 минуты → проверка выполняется, запись появляется в «Графиках».
2. Перезагрузить базу через 5 мин после проверки → повторной проверки сегодня нет.
3. Сессия: короткое нажатие кнопки → `zZz` на экране, экран гаснет, в журнале «Wi-Fi выключен: кнопка», «Уход в сон на …». Нажатие кнопки → база просыпается, значок Wi-Fi, страница снова открывается. Закрыть страницу и подождать 10 мин → уснула сама («нет активности»).
4. **Плановое пробуждение:** поставить проверку модуля через 5 мин, уложить базу спать. В момент проверки: экран включается, `#1` и `NN%`, значка Wi-Fi нет, роутер не видит клиента (кроме дня тихой синхронизации времени). После — снова сон.
5. Во время планового пробуждения нажать кнопку → включается Wi-Fi-сессия.
6. Во время ручного полива нажать кнопку → насос стоп, клапан закрыт («выключение/обновление»), потом сон. Во время полива подождать таймаут сессии → база **не** засыпает, пока полив не закончится.
7. Мультиметр на входе MOSFET помпы (GPIO20) во сне → 0 В. На GPIO2 во сне → 3.3 В (линия обесточена), на жиле «3V3 линии» → 0 В.
8. Дрейф часов: уложить на сутки с `ntpDays = 0`, затем открыть UI и сравнить время в шапке до синхронизации с реальным → записать в README §8.
9. Замерить ток от 18650 в сне (с горящим и без красного LED), в сессии и при плановой проверке → записать в README §8.
